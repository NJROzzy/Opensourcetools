Welcome to Amalgam

Amalgam helps you design and scale real projects with free, open-source tools. We’ll start with a simple example, then open the System Design Canvas to put it into practice.

Design a shared to-do list

Two roommates need to see the same list, add tasks, and mark them done. Start with three boxes and follow one new task through them.

  1. BrowserSends a new task
  2. App serverChecks and saves it
  3. DatabaseKeeps the shared list

Test it by adding a task in one browser and refreshing the other. If a save fails, keep the task text so the user can retry.

Scale when you hit a limit

Start with one server and one database. If the list gets slow, measure where the time goes. Check the query and consider an index if the database is slow. If the app server is overloaded, consider adding another server behind a load balancer.

Use the canvas to sketch the change and decide what to test next.

What you can achieve

  • Turn an idea into a plan. Map a web app from its interface to the server and database.
  • See how tools fit together. Trace a sensor reading through the firmware, network, and dashboard.
  • Plan for growth. Sketch where to add capacity as traffic or data increases, then export the diagram to share.

Take the next step in the canvas

Try the to-do list: start with a browser, an app server, and a database. Connect them and label what travels between them. When you’re ready to plan for more traffic, sketch where a load balancer would go.

    What makes a tool eligible

    A tool is listed only if it can be used at no cost and its source is published under a recognised open licence (MIT, Apache-2.0, BSD, GPL, MPL and similar). For open-weight AI models, only releases under an open-source licence such as Apache-2.0 are recommended. Nothing here requires a paid plan. Where a project moved to a source-available licence, its open community fork is listed instead.

    Every tool is tagged with each domain it serves, which is how the map places it. Treat the list as a set of parts, not a ranking.

    Licences change. Always check the licence file in a project's repository before you build on it.
